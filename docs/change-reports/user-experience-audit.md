## 优先修复：确实影响理解或学习安排

### P1-1 复习入口丢失词义语境

**复现：**2010 Text 2第14句点击`epidemic`，本句义正确为“广泛蔓延的问题（流行病比喻）”。标记后从复习清单再次打开，标题仍显示Text 2，却变成“流行病；流行性的”“本篇作名词，指跨地区传播的疫情”，同时搭配仍是`a virtual epidemic`。同一个卡片内部发生医学语境与婚姻语境混用。

**依据：**`app/study-app.tsx:1515`和自定义清单入口传入固定`"review"`作为sentenceId，只保存词条key，没有保存当时出处。

**建议：**保留现有稳定规范词条，复习项另存`articleId + sentenceId/sourceId + headword`和词义标识。多个语境可聚合在一个词下，但默认回到用户标记的那一句。旧清单迁移找不到唯一来源时让用户选例句，不猜一篇当“本句”。

**验收：**从正文、年度词表、复习和自定义清单进入同一出处时，本句义/词性/用法/替换一致；用`epidemic`的医学义与比喻义做回归样例。

### P1-2 “今日待复习”不按到期时间计算

**复现：**给`epidemic`标记后评为“正确”，队列显示“1天后”，左侧仍显示“今日待复习 1”。

**依据：**`app/study-app.tsx:805`统计全部标记，而非`dueAt <= 当前时间`；`:1511`用固定`intervalDays`显示“几天后”，没有依据实际到期日期计算剩余天数。

**建议：**区分“今日到期”“逾期”“全部收藏”；按真实dueAt排序，评分后立即移出今日队列。展示“明天”“9月18日”“逾期2天”，而不是永远显示最初设定的间隔。

**验收：**用固定时钟测试当天、隔天、跨月和离线重开，人数与列表一致；“正确”不能使明天的任务仍计入今天。

### P1-3 带标点词组出现次数错误

**复现：**2010年度词组表搜索`in the`，`In the U.S.`显示“0次”，但2010完形第9句确实有该表达，词卡也能展示它。

**依据：**`app/study-app.tsx:501`用首尾`\b`匹配整段文本，句点结尾表达不适合这个边界规则；通用`countPhrase`也采用类似写法。

**建议：**次数和出处统一取自原文定位索引，不再各入口重复拼正则。明确“原文表达次数”和“同一规范结构次数”，保留正文/题干/选项来源标识，允许筛选统计口径。

**验收：**覆盖`U.S.`、缩写、连字符、弯引号、跨行空白、原文实例和规范结构；每条已收录来源的原文表达不能显示零次。

### P1-4 自测说明题号固定，和当前真题冲突

**复现：**2010 Text 2自测顶部写“完成第11–14题”，实际列出26—30题。

**依据：**`app/study-app.tsx:1369`阅读分支为固定字符串。

**建议：**从当前文章题目显示题号生成范围；计时默认值也按题型/题量提供可调整值。只改说明，不修改题干、答案或原文。

**验收：**2000阅读、2010 Text 1/2及不同题量文章的说明均与实际题号一致。

## 次优先：减少操作和误解

### P2-1 展开讲解被当成“学习进度”

**复现：**Text 2展开第1句，进度从0/19变成1/19；收起同一句又回到0/19。用户会以为学过的内容消失了。

**依据：**`app/study-app.tsx:791`直接计算expanded集合。

**建议：**最小修改是改名“已展开”；更好的学习流程是另存“已读/待复习/已掌握”，折叠仅影响展示。不要用停留秒数自动判定掌握。

### P2-2 中文搜索遗漏已有语境词义

**复现：**2010年度表搜索`epidemic`得到1项及6次；搜索正文卡已有的“广泛蔓延”却是0项，只能搜到年度代表释义“流行病”。

**依据：**`buildYearWordItems`挑一个代表出处，搜索只扫该项meaning等展示字段（`app/study-app.tsx:1913`附近）。

**建议：**搜索索引包含同词的所有已审核语境义、原文词形、规范词组及例句；结果按词条聚合，展开列出“医学义/比喻义＋出处”。保留已有mean/means语境归一化修复，不重新合并不同词位。

### P2-3 出处可读，但不能直接回原句

**复现：**展开`epidemic`“出现次数与年份”，能看到6条正文/题干来源，但各条是普通文字，不能直接定位并切换到该句语境。

**依据：**`app/study-app.tsx:2630`把出处渲染为段落。

**建议：**增加“回到原句/题干”，切换正确年份与篇目、滚动并短暂高亮目标；词卡保留返回历史。来源维持稳定sourceId，不仅靠例句文本匹配。

### P2-4 手机小按钮和目录占用注意力

**观察：**390px手机没有主体横向溢出，账号表单可用；但“结构”按钮样本仅约25.6×14.4px，容易与相邻单词误触。目录需要横向滚动，翻译自测首屏主要仍是目录、文章简介和计时设置，答题区在更下面。

**建议：**保留现有视觉，扩大结构入口实际点击区域；增加“显示/隐藏词组标记”，让整篇初读不被反复出现的“结构”打断。进入学习/答题后目录可收为“2010 · Text 2”的紧凑选择器，计时器可折叠。

**验收：**390px、长词及高密度词组都不重叠；保留键盘焦点和屏幕阅读器名称；不用取消词组点击来掩盖问题。

### P2-5 知识量增长会增加首屏成本

**证据：**构建后的主学习包约2,059,125字节，gzip约664,884字节；本次生产浏览器观察压缩传输约632,954字节。单次资源加载约4.2秒，受本机网络/代理影响，不当成所有用户的速度或标准性能测评。正式构建也有大分块提醒。

**建议：**按年份/篇目按需加载精审内容，词卡细节与年度搜索索引分开加载，首次只提供正在读的文章。不要每点一个词再次全语料遍历；离线功能改为明确的“下载本年内容/已下载版本”。

**验收：**用固定设备、固定网络及冷/热缓存分别测首屏可操作时间；拆包后复测离线、搜索、词卡和统计，不能牺牲知识覆盖。

### P2-6 同步还需要备份与冲突处理

**代码风险，未用真实账号复现：**密码版本已解决登录未读云端就上传、以及未修改快照时间被刷新等风险；但底层仍是整份JSON最后写入覆盖，单一浏览器存储键也未按账号分开。多设备同时写不同笔记、共用设备切换账号仍值得专项处理。

**建议：**先加入导出/导入备份和最近同步时间，再做每账号本机存储分区；云端写入增加版本检查，冲突时保留两份或按稳定条目合并，不能静默清空本机记录。这个改动须有独立数据迁移与双设备测试，不适合顺手大改。

## 知识库结构的优化方式

现有“规范词条＋句子语境＋语料来源”方向正确，不需要另建一套平行词库。重点补齐所有入口的关联：

| 层次 | 保留/补充内容 | 用途 |
| --- | --- | --- |
| 稳定规范词条 | 原形、词族、通用搭配和辨析 | 避免每篇重复建词，个人笔记继续关联稳定ID |
| 已审核语境 | articleId、sentenceId/sourceId、词性、本句义、用法、整句替换 | 正文和复习不串义，中文搜索覆盖多义 |
| 出现位置 | 正文/题干/选项、原词形、位置边界 | 同一索引同时服务次数和回到原文 |
| 词组原型与实例 | canonicalForm、sourceExpression、来源列表 | 不把原句实例与抽象结构混成一个计数 |
| 学习记录 | 词条ID＋所学语境ID、dueAt、用户状态 | 区分“认识这个词”和“懂这个语境” |
| 内容审校元数据 | 来源、人工审核范围、修订记录 | 有据可追溯；字段齐全不等于语义正确 |

建议补充的高价值回归：`epidemic`两种语境在全部入口一致、`mean/means`不误并、`In the U.S.`标点计数、复习到期时钟、中文语境检索和出处导航。语义审查继续按篇推进，不用自动生成占位释义充数。

## 推荐实施顺序

1. **准确性修复包：**复习语境、到期队列、词组计数、自测题号。每项有上述复现及验收，不动原卷正文。
2. **顺手学习包：**进度与展开分开、语境搜索、出处跳转、手机点击区域；继续沿用现有页面风格。
3. **长期可靠性包：**记录备份、账号隔离、版本冲突、按年拆包和离线下载状态。数据迁移与性能测量独立安排。

补充：当前年份选择只有2000、2001、2010，未导入目录项会重复出现“待精审”。建议将“可学习范围”与“计划导入”分开说明，避免让新用户误以为网站故障；不能为填满目录而编造缺失真题内容。
