# 登录服务检查与重试修复

## 范围与依据

用户在安卓 App 中看到「邮件服务待接入」且无法登录，随后明确暂不连接手机、先修代码。本次仅修复网站公共账号面板和会话检查；安卓 WebView 使用同一网站，发布网站后即可使用修复。

匿名访问正式站 `/api/auth/session` 返回 HTTP 200，`configured` 与 `passwordConfigured` 均为 `true`。这说明接口报告配置存在，不能据此证明实际邮件投递成功。代码中两项配置初值均为 `false`，原检查未校验 HTTP 状态与响应结构，且静默忽略请求失败，因此网络异常也会显示「邮件服务待接入」，访客恢复联网后不会重查。本轮未取得手机失败请求，不能断言手机故障的具体网络原因。

## 实际修改与安全边界

- `app/auth-session.ts`：校验 HTTP 状态、能力字段及用户结构；12 秒超时覆盖请求和响应体读取；支持取消，错误均明确提示重试。
- `app/study-app.tsx`：区分检查中、成功和失败；支持手动重试、访客重连及重新打开错误面板时重查。只有有效成功响应可以执行原账户恢复流程；检查失败不删除本机账号归属或切换为访客。独立请求代数、账号代数及取消机制阻止旧结果覆盖新状态。
- `app/api/auth/session/route.ts`：会话读取异常返回 HTTP 503 和通用错误码，不返回虚假的匿名成功结果、不删除 Cookie；密码表查询故障仍保留已验证用户，并通过 `passwordUnavailable` 标记临时不可用。
- 邮件不可用时保留密码登录；密码暂不可用但邮件可用时保留验证码入口。双服务不可用时使用中性提示并提供重试。
- Cookie、验证码、密码认证规则、学习记录结构及同步合并算法保持原行为；没有接入新服务，没有访问正式个人数据、发送邮件或输入真实登录凭据。

信任边界仍为同源会话接口和服务端认证。客户端检查只决定界面与本机恢复时机，不授予服务端访问权限；HTTP 错误、非 JSON、缺字段和超时均不能成为登出证据。测试用隔离数据库和合成邮箱验证状态丢失风险。
