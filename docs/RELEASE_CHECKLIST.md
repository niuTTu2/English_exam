# 单篇精简审计与交付流程

自2026-09-16起，本文件是日常审计的唯一执行清单。内容要求仍见 `CONTENT_QUALITY_STANDARD.md`；缩减的是重复审计、重复测试与重复报告，不是精审内容。用户不逐篇复核，执行者在录入时完成语义判断；自动测试不能证明翻译或答案必然正确。

## 1. 接续与来源（开始时一次）

- 检查 Git 状态、远端与 `IMPORT_PROGRESS.md`，确定唯一待做篇目，保护已有修改。
- 确认能读取用户原卷，记录文件名及页码/段落位置；核对试卷类型、正文、题干、选项、题号与答案依据。
- 原卷与公开解析有异文时记录差异，不静默混合版本。来源缺失或关键语义/答案未解决时停止该篇交付。

## 2. 精审随录入完成（不再多轮全量复读）

- 原句完整，`chunks` 可拼回原文；`trunk` 按原文词序删减，不以意译代替主干。
- 显式填写 `beginnerSyntax`，说明整组词的形式、功能和修饰对象；真实从句含内部主谓宾/补语及翻译顺序，分清从句、同位语与非谓语。
- 两层翻译不增删命题，尤其注意否定、比较、指代和逻辑。复用既有折叠界面，不默认展开全部细节。
- 正文、题干、选项词形均可查；原文词组片段与规范结构分开；重复词复用稳定条目且本句义隔离，词形/原形/词族不混算。
- 可点击关联先有实质内容。原句同义替换需保持自然语法与原命题，检查目标词条；不要为凑“每句一项”生成不成立的替换。
- 答案、定位和四项理由互相支持；同步答案清单、年度目录、词表和统计入口。

完成后只集中复看仍有疑点的条目，不反复审计无变化的旧文章。无需复制本节为逐项勾选的长报告。

## 3. 按变更范围选择检查

| 变更范围 | 必要检查 | 不必重复做 |
|---|---|---|
| 仅流程/说明文档 | `git diff --check`；检查入口、进度、命令与权限说明一致 | 内容测试、构建、手机电脑回归 |
| 单篇内容及必要目录、类型、词库接入 | `npm run quality:content`、`npm run build`、`git diff --check` | `npm run quality`、`npm test`、每篇完整移动端复测 |
| 已获授权的 UI/渲染逻辑修改 | 上述内容检查与构建；`npm run lint`；构建后执行下方 UI 测试；抽查受影响手机/电脑交互 | 再运行会重复构建的 `npm test` |
| 已获授权的依赖、框架或跨模块行为改动 | `npm run quality` 与相关专项验证；记录影响范围 | 再单独重复整套中的同一命令 |

构建后的 UI 测试命令：

```sh
node --test --test-concurrency=1 tests/ui-components.test.mjs tests/rendered-html.test.mjs
```

数据结构、解析或归一化逻辑改变时，除内容检查和构建外，补充针对受影响路径的回归测试；涉及运行逻辑再加 lint 与相关现有测试。账号、同步、部署修改不属于普通精审授权。

执行原则：

- 同一内容快照各必要检查通过一次即可。`quality` 包含 lint、内容测试及 `npm test`；`npm test` 又会构建，不要叠加运行。
- 失败后先汇总同类问题、一次修正，再重跑受影响检查。不得跳过失败、降低断言、删除链接或精审字段来过关。
- 通过后又改内容/代码时，旧结果不代表新快照，须重跑受影响项；仅补报告结果不需要重新构建。
- 只新增覆盖本篇特有风险的必要断言，如题号/答案、复杂从句边界、语境隔离和替换链接；复用既有通用测试，不复制大量重复测试。
- 缺依赖、命令或平台支持须记为未运行/环境阻塞，不能记为通过。Windows 构建可用 WSL 或 Docker。

## 4. 一份报告、一个提交

1. 按 `CHANGE_REPORT_TEMPLATE.md` 生成本篇唯一报告，记录来源、重点判断与实际结果。更新 `IMPORT_PROGRESS.md` 的总表、分表、接续点。
2. 检查 diff，仅暂存本篇及必要接入文件。关键疑点全部解决、必要检查通过后创建独立提交。
3. `git push origin main`。若远端变化先获取并核对他人修改；不得强推。权限失败/分支保护时停止并报告。
4. 交付消息记录 SHA 与推送结果。有权限则核验对应 SHA 的 Cloudflare 部署状态；无权限写“推送成功，部署未核验”，不无限等待或编造成功。
5. 部署失败先处理/报告；仅未能观察部署时可继续本地下一篇，但不能宣称线上更新。下一篇始终另作提交。

报告在提交前可写“待提交/待推送”；成功后的 SHA 留在交付消息与 Git 历史，不要为将本提交自己的 SHA 填回报告反复 amend、重建和推送。

## 5. 上下文中断与交接

中断前在台账记录当前篇、完成阶段、疑点和下一步；未通过交付检查时不得标记已完成。接手者先读这些记录与 Git 差异，不依赖聊天记忆。历史报告中的旧版重检查要求仅作当时记录，后续执行以本流程为准。
